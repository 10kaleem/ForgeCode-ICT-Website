\section{Introduction}

\subsection{The Organisation}
Saeed Book Bank is an online book store. Its website describes it as one of the largest online book stores. Visitors can search and buy books on many subjects, and the store offers special prices and discounts \cite{sbb}. The original website also sells magazine subscriptions and has member sign-up and an order status page. This project follows the course handout \cite{handout}.

\subsection{Problem Statement}
The Saeed Book Bank website has most of the things a book buyer needs, but its user interface is outdated and unattractive. This is the main problem we want to solve. When we checked the home page on 21 November 2026, it looked old and crowded. Its buttons and dividers are small picture files, its pages have short codes that end in .asp, and it has many links with no clear order. Table~\ref{tab:problems} lists the problems we found and their impact.

\begin{table}[H]
\centering
\caption{Problems found on the current website (checked on 21 November 2026) \cite{sbb}}
\label{tab:problems}
{\small\singlespacing
\begin{tabularx}{\textwidth}{|>{\bfseries}p{2.6cm}|Y|Y|}
\hline
\rowcolor{black!10}\textbf{Problem} & \textbf{What we saw} & \textbf{Impact}\\
\hline
1. Outdated and unattractive UI (main problem) & The footer notice runs from 2000 to 2014. Buttons and lines are small picture files. The page looks old and cluttered. & Visitors may think the store is not active. They trust it less and may leave quickly.\\
\hline
2. Crowded navigation & Twelve links in the top area, in two rows plus a separate line. & Visitors do not know where to click and take longer to find things.\\
\hline
3. Unfinished parts & A ``Coming Soon'' link is in the main menu. The newsletter ``Submit Request'' button points to ``\#''. & Visitors click links that lead nowhere, and the store may lose interest.\\
\hline
4. Hard-to-read prices & Prices such as PKR 12589.4435 have four decimals, and some are shown with US\$ or UK pound prices. & Prices look like mistakes and are hard to compare.\\

\subsection{Objectives}
The project has the following objectives.
\begin{enumerate}
  \item Replace the old look with a clean, modern design that uses one palette of five colours, two fonts and the same layout on every page.
  \item Build six main pages (Home, Books, About, Contact, Suggestions, FAQ) that share the same header and footer, with every link working.
  \item Give each book its own details page, with a button to order it on WhatsApp.
  \item Show prices in whole rupees, with the special price clearly shown.
  \item Make the layout work from 360 px wide (small phone) up to a desktop screen, with no sideways scrolling.
  \item Pass the W3C HTML and CSS validators with no errors.
  \item Add form validation and at least two more interactive features in Phase 3.
\end{enumerate}

\subsection{Target Users}
\begin{itemize}
  \item \textbf{Book buyers:} students, teachers, researchers and general readers who look for books and prices on a phone or a computer.
  \item \textbf{New visitors:} people who do not know the store and decide quickly if they trust it.
  \item \textbf{Store owner and staff:} they need a site that is simple to read and easy to update.
\end{itemize}

\subsection{Scope}
\textbf{Included in Deliverable 2.} The static front-end website, made with HTML and CSS only. It has six main pages and one details page for each of the 13 books. Each book page has a WhatsApp order button. The Contact and Suggestions forms are laid out with labels, but their checks are added in Phase 3.

\textbf{Not included.} The shopping cart, user login, membership sign-up, order status and online payment are not part of this project, because they need a server and a database. The site does not ask for passwords or card details. JavaScript features (form checks, subject filter, FAQ accordion, menu button) are in Phase 3.

\textbf{Content.} The book information and cover images come from the Saeed Book Bank website and are used only for this course project. The footer credits the store and ForgeCode.

\subsection{User Stories}
\begin{enumerate}[label=US\arabic*.]
  \item As a book buyer, I want to browse books by subject, so that I can find the kind of book I want quickly.
  \item As a student using a phone, I want the pages to fit my screen, so that I can read them without zooming.
  \item As a customer, I want to see one clear price for each book, so that I can compare books easily.
  \item As a customer, I want to order a book on WhatsApp from its page, so that I do not need an account.
  \item As a visitor, I want to send a question through a form, so that I can ask about a book I cannot find.
  \item As the store owner, I want a clean and modern site, so that new visitors trust my store.
\end{enumerate}

\section{Front-end Implementation}

\subsection{HTML Structure}
Every page uses the same main parts: a header with the navigation, a main area, and a footer. The header is a \texttt{header} element and the navigation is a \texttt{nav} element. The main area is a \texttt{main} element, and each section inside it is a \texttt{section} element. Each book card is an \texttt{article}. The footer is a \texttt{footer} element. Each page has one \texttt{h1} heading, and the other headings go down in order (h2, then h3).

Listing~\ref{lst:html} shows a short excerpt of the header and navigation used on every page.

\begin{lstlisting}[caption={Header and navigation (shared by every page)},label={lst:html}]
<header id="site-header">
  <div class="container header-inner">
    <a class="logo" href="index.html">Saeed Book Bank</a>
    <nav aria-label="Main navigation">
      <ul class="nav-list">
        <li><a href="books.html" aria-current="page">Books</a></li>
        ...
      </ul>
    </nav>
  </div>
</header>
\end{lstlisting}

The \texttt{aria-current} attribute marks the page the visitor is on. The \texttt{aria-label} tells screen readers what the navigation is for.

Each book page has a form-free ordering button, which is a normal link. Listing~\ref{lst:wa} shows the WhatsApp link. The message text is written with the book name, author and price, and is encoded so it works in a link.

\begin{lstlisting}[caption={WhatsApp order link on a book page},label={lst:wa}]
<a class="btn btn-whatsapp"
   href="https://wa.me/92123456789?text=Hello%2C%20I%20would%20like%20to%20order%20...">
  Order on WhatsApp
</a>
\end{lstlisting}

\subsection{CSS Design}
The site uses one external style sheet, \texttt{css/style.css}, linked from every page. Colours and fonts are stored once as variables at the top of the file, so a change is made in one place. Layout uses Flexbox for the header and footer, and Grid for the book cards and the two-column contact page. Class names describe the parts (for example \texttt{.book-card}, \texttt{.btn}) and the ID selectors name the page sections (for example \texttt{\#site-header}).

Listing~\ref{lst:css} shows the variables and one class used on the buttons.

\begin{lstlisting}[caption={Colour variables and button style},label={lst:css}]
:root {
  --blue: #1B3A5C;
  --amber: #C8892B;
  --cream: #FAF7F2;
  --font-heading: Georgia, "Times New Roman", serif;
}
.btn {
  background: var(--amber);
  color: #222222;
  padding: 12px 24px;
}
\end{lstlisting}

\subsection{Responsive Layout}
The site uses a media query for screens 700 px wide or narrower. On these screens the header stacks, the book cards show two per row, and the book detail and contact pages show one column. The page was checked at 390 px wide, and no page scrolls sideways at that width or at desktop width.

Listing~\ref{lst:media} shows the media query.

\begin{lstlisting}[caption={Media query for phones and small screens},label={lst:media}]
@media (max-width: 700px) {
  .header-inner { flex-direction: column; align-items: flex-start; }
  .book-grid { grid-template-columns: repeat(2, 1fr); }
  .book-detail, .two-col { grid-template-columns: 1fr; }
}
\end{lstlisting}

\subsection{Design Decisions}
\begin{itemize}
  \item \textbf{One palette and two fonts.} The old site uses many colours and styles. We use five colours and one accent colour for the WhatsApp button, so the pages look calm and consistent.
  \item \textbf{No animations.} The site does not use moving effects, so it stays simple and easy to read.
  \item \textbf{Prices in whole rupees.} The old four-decimal prices are replaced by whole PKR amounts.
  \item \textbf{Ordering by WhatsApp.} We did not build a cart, login or payment, because these need a server. WhatsApp lets the store take orders with no backend.
  \item \textbf{Standard elements first.} The FAQ uses the built-in details element, so it works without JavaScript.
  \item \textbf{Placeholder number.} The WhatsApp number is a placeholder and must be replaced by the store's real number.
\end{itemize}
